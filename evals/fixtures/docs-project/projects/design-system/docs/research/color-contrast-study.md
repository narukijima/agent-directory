# コントラスト基準を層ごとに変えるべきか

## 問い

tokens、primitives、patternsで異なるコントラスト基準を持つべきか、単一基準に統一すべきか。

## 目的

`docs/DESIGN.md`の横断的関心事を1つの判定へ固定できるかを決める。

## 仮説

層ごとに基準を変えると、同じ組み合わせで判定が割れ、レビューコストが上がる。

## 方法

既存3プロダクトの実装済み画面から、コントラスト比が境界付近にある組み合わせを抽出して比較する。

## 使用した証拠

- `inputs/current-components.csv`の実装済み組み合わせ

## 観測・結果

境界付近の組み合わせで、層ごとの基準を採ると同一画面内で判定が割れる例が確認できた。

## 反対証拠・限界

装飾専用の要素では単一基準が過剰になる場合がある。対象は3プロダクトに限られ、母数が小さい。

## 現在の結論

このProjectでは単一基準を採る。装飾専用要素は例外条件として`docs/DESIGN.md`へ明記する。

未昇格。母数が小さく適用範囲を確定できないため、Project内の結論に留める。
